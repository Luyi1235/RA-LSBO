# 24小时可行性与零调用演练

工作机：AMD Ryzen 9 9950X（16 核、32 逻辑线程），物理内存 33,340,878,848 字节；RTX 5060 显存 8,151 MiB，检查时空闲 7,101 MiB，GPU 利用率 3%。这些是采样瞬时值，不是负载峰值。原 `Rcaide_vsp` PyTorch 为 `2.8.0+cpu`，`torch.cuda.is_available()` 为 false，不能声称可用 GPU 训练，也不得改变环境来规避本轮限制。

历史 P3 一份 `iteration_000/state.npz` 只读加载为字节并重复 SHA-256：32 个任务，每个任务 20,000 轮，Windows spawn；结果分别为 1/2/4/8/12/16 进程 9.953/5.047/2.625/1.422/1.141/0.922 秒，全部完成。这只是模拟 CPU/内存读取负载，并非实际 VAE 推理、GP 拟合、算法提案或飞机评价；并发期间 CPU、内存峰值和 GPU 训练负载并未完整采集。不能由此推断真实算法加速。现阶段正式实验无可推荐进程数，离线开发可从 4 开始，须在未来单独批准的代表性资源测试中评估 1/2/4/8/12/16 的逐算法吞吐、峰值 RAM/VRAM、系统开销和结果一致性。

PR #36 的历史 P3 数据仅含两种 H2 算法：576 次提案累计 1345.673 秒，平均 2.336 秒。七方法全部套用这一时间的示意串行下限约 173.8 小时，未含审计、资源争抢、排队和其他固定开销；其他五种算法尤其 CBOB-adapted 的时间未知。即使假设 8 倍理想加速也约 21.7 小时，剩余不到 2.3 小时覆盖全部未知开销，不能保证 24 小时。**本轮无法证明七臂确认实验在 24 小时内可完成。**

一个供另行审查、非已批准确认的示例：每任务从 1024 改为 128 独立种子时，七臂相同初始化和单臂预算下总调用 296,960 / 8 = 37,120，按同一不可信串行比率约 21.7 小时；这不是运行预算或 24 小时承诺。以单个配对、无平局、双侧 0.05 精确符号检验为示例，真实条件胜率 0.60 时 128 对功效约 0.595，0.65 时约 0.922；64 对分别约 0.298、0.618。使用 SciPy 精确二项分布枚举，无多重比较调整；实际平局、非独立、分任务及多个主要比较会降低有效信息或需改变检验。因此不可把缩小后的计划宣称等价原确认研究；需预先确定真实效应、非平局比例、主要假设与多重校正后重新设计。
