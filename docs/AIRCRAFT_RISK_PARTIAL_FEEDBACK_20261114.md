# 提前终止的约束反馈能否改善飞机设计的首次发现

PR102 中，按失败类型分别规划的两步选择，在初值无解人群中，相对合并失败的两步选择无风为 0 胜 5 负 4 平、平均晚 3.11 次，逆风为 4 胜 2 负 6 平、平均早 0.58 次。逆风去掉任一种子的均值范围跨过零。两臂在全部 21 个初值无解的工况–种子组合中，于第 5–7 次调用首次选出不同点。分阶段一次机会在两个工况都优于直接可用 GP 的配对均值，但相对于连续工程约束模型无风较差。下一轮检验中止时的有序约束信息是否真正改善首次发现，固定模型与取点规则以识别该机制。

## 固定模型与反馈

所有风险模型使用相同的显式结构特征、分组核网格、EP 近似、约束及联合可行概率乘积。真实评价器相同。可信的精确约束值在任何试验臂都可使用，包括提前终止前已精确得到的结构约束。未知、数值或基础设施错误没有可信工程标签。

| 臂 | 首个可用解之前的约束证据 | 选点 |
| --- | --- | --- |
| feedback_exact | 仅可信精确观测 | 最大联合可行概率 |
| feedback_sign | 精确观测和由区间可确定的约束符号，符号用零阈值半区间表示 | 最大联合可行概率 |
| feedback_bounds | 精确观测和评价器完整返回的约束区间 | 最大联合可行概率 |
| feedback_coverage | 约束模型使用完整反馈以便诊断 | 显式特征 maximin |

最大联合可行概率的三臂共用同一混合似然。sign 将可确定的区间标签降为 `g ≤ 0` 或 `g > 0`，跨零或符号未知区间在该臂留空。因此 bounds 对 sign 同时检验有效符号之外的界幅值和符号未知时的约束界。以 SOC 头为机制诊断，本模型在 SOC 提前中止时给出正下界，SOC 头的比较保留相同的可判定符号，用来查看界幅值是否还能增益。这些界不是精确最终裕量。目标能耗与 VAE 的训练仅使用原代码支持的精确目标值。在首个可用解后，四臂统一使用完整的约束证据和潜空间能耗 CEI。末端能耗属于探索性结果。

## 设计、终点、诊断

两工况均为 140 km、20 s 步长，分别无风和 4 m/s 巡航逆风。两工况共享 16 个新种子的采样初始化与候选生成设定。各工况独立评价。每个种子共享 4 个初值与初始 128 点池，每臂再完成 16 次评价，不增补候选。每种子 32 个相同留出点在四臂结束后评价。

主比较为 bounds 对 sign，在每工况初值无可用设计的种子上报告。首次同时完成任务、返回可信精确能耗且满足所有工程约束的调用记为 T。到第 20 次仍无解时保留原始空值，以 21 计算受限调用数和胜负平。报告受限均值差、种子内差、留一敏感性和第 20 次发现率。次比较为 sign 对 exact、bounds 对 exact、bounds 对覆盖。全样本配对保留初值已解的种子。

覆盖臂在每个预设检查点从同一份评价历史分别拟合三种监督，用同一留出样本评分，以区分监督证据效应与在线选点诱发的训练分布效应。报告联合可行和 SOC 的 Brier、AUROC、正例数、可行召回及测试标签覆盖。仅对有可判定留出标签的设计评分。报告首选分歧、反馈类型和临界种子。若 bounds 对 sign 的首次发现效应只出现在一个工况或依赖单个种子，将其作为探索性证据。若同轨预测改善但首解没有改善，应分别报告统计预测与在线决策结果。结果用同一简化飞机的两个工况验证机制。

| 配置 | 种子 | 共享初始 + 独立在线 + 留出 | 总调用 |
| --- | ---: | --- | ---: |
| feedback-smoke | 1 | 4 + 12 + 16 | 32 |
| feedback-nominal | 16 | 64 + 1,024 + 512 | 1,600 |
| feedback-headwind | 16 | 64 + 1,024 + 512 | 1,600 |

合计 3,232 次简化飞机调用，RCAIDE/MDA 0 次。两套正式输出各有 64 条 discovery_pairs.csv 数据行。analysis.json 内的 discovery_summary 给出初值无解人群的统计。metrics.csv 的 common_joint_* 与 common_soc_* 行是覆盖臂同历史配对分析。

## 工作机

GitHub 提交与本地预期 SHA 对齐后，在现有 Rcaide_vsp 环境先运行 `python -m unittest discover -s tests -p "test_aircraft_risk*.py"`。使用 `run_aircraft_risk_cold_start.py` 依次执行三个配置的 plan、run、verify、analyze。结果目录在 worktree 外，技术失败时保留账本及日志。将三套原始证据、分析、日志、环境和 SHA256SUMS 上传到独立结果分支。
