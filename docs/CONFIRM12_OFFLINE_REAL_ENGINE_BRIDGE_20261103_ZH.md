# 确认实验：历史优化器离线闭环增量

此分支基于 PR #40，不授权任何真实模型调用。`OfflineHistoricalTrial` 接入原始 H1 优化器的 `propose/accept`，保留原方法名，不把历史方法默认为确认算法。它复制共有历史和候选池，检查候选、合同、解析约束与已有设计，并在未结算或异常后停止；反馈必须对应待处理候选。它不含评价器、正式调度和可信账本，不能作为生产 runner。

Windows/Rcaide_vsp 下，使用禁止飞机 evaluate 的进程补丁，以测试构造反馈执行真实历史 random 策略：12 个 spawn 子进程各完成一次提案与接收，进程 ID 与各自历史摘要均不同。这个测试不拟合 GP 或 VAE，不验证其他六臂、长期稳定性、峰值内存、断电恢复或真实模型吞吐。它不是 12 工人正式资源资格。

七臂依旧全部 BLOCKED：历史 random、onehot、latent 及 hybrid 引擎仅有接口或离线部件；主 RA-LSBO 的确认数学定义和映射、反向表征闭环审计、interval-as-missing 的原始决策历史隔离和 CBOB 的可追溯实现仍未完成。现有事务账本仍为 SIMULATED_ONLY，真实模型适配、审批凭证和独立审计未完成。两任务的独立资格需要单独授权的真实评价，历史种子排除仍有未读档案。

用户已取消正式实验 24 小时限制，仍需要 12 个完整优化工人的资源、信息隔离和持续稳定性验收。PyCharm 入口默认仅预检，正式执行仍拒绝；不得通过本文件或本次测试将状态改为 READY。
