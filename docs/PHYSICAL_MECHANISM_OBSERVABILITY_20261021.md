# 真实机制的观测范围

本次检查只读原始worker和风险适配器，不改变v5实验。
源码身份由v5的 `plan.json` 和 `source_snapshot` 固定：
`927e248265a5e9a8c4581697d5105e12c3f4a6abbdfb6bcaedd20afb521d0adb`。
接口支持五种标签，并不意味着当前真实worker能分别观测所有五类。

## 已有路径

| 机制 | 当前真实采集路径 | 限制 |
| --- | --- | --- |
| 几何生成失败 | 原生候选评估器捕获通用异常；廉价几何拒绝另记预检拒绝 | 原生worker未直接返回该机制标签，预检拒绝不能补作隐藏失败正例 |
| 网络配置失败 | `rebuild_propulsors` 内错误被外层归并为 `evaluation_error:<异常类>` | 缺少独立网络失败的结构化来源，错误发生在procedure前时没有procedure阶段迹线 |
| 电机设计失败 | 电机求解回调抛出错误后同样进入通用捕获；成功结果有电机记录 | 通用 `ValueError` 不能单独识别电机失效，也不能区分设计问题和接口问题 |
| 任务求解不收敛 | `DomainSolveError`、明确失败任务段和求解记录 | 当前真实训练及新校准正例属于此类；局部邻域不代表多个独立失效区域 |
| 能量审计失败 | 原始指标 `energy_audit_status=failed` 被适配器识别 | postprocess外层也会为部分其他异常设置该标志，未来正例还需核对实际审计报告和异常来源 |

证据代码位于原工程：

- `problems/x57/model/candidate_evaluator.py`：`evaluate_candidate` 将构型应用、
  翼型、推进器重建及procedure中的异常归并为通用状态。
- `problems/x57/evaluation_diagnostics.py`：只包装procedure步骤；之前发生的
  翼型或推进器构造异常不经过这些步骤的异常记录。
- `problems/x57/motor_design.py`：电机参数校验和硬边界会抛出 `ValueError`，
  当前没有独立的失败电机报告。
- `problems/x57/worker.py`：将原始异常状态、已有指标和求解报告转交适配层，
  没有直接产生前三种机制状态。
- `problems/x57/postprocess.py`：postprocess外层捕获若干异常时统一标记审计失败。
- 本项目 `ra_lsbo/legacy.py`：前三类需要明确机制状态；未识别的通用异常
  保留未知，当前只保存已有阶段与来源，不据异常类猜测这些机制。

目录清单纳入的19个终止历史目录中，非普通完成状态只观察到任务求解失败。
本轮实际正例和有效能耗部分观测仍按冻结标签契约处理。以上代码路径
分析不产生新训练样本，也不能证明未观察类别在整个合法域内绝不发生。

## 后续数据采集条件

若继续研究前三类，须在新的采集契约中补充构型生成、网络连接、转子
设计和电机参数求解的独立开始、成功、失败及异常来源记录，并保留原始
请求响应。可以在RA自己的worker包装层增加诊断，原工程源码保持只读。
新增元数据要经过物理输出一致性核验，不能悄悄用于重写本轮结果。

形成机制正例还需要可审计的设计相关失效证据；阶段名称和通用异常类
本身不足以排除依赖、资源或程序错误。能量审计类别还须验证审计报告
确实失败，避免把审计后的其他后处理错误当成能量不守恒。

因此当前的真实数据缺口包括失效场景覆盖和异常可辨识性。
本轮可以交付真实任务失败训练、完整短程系统对照与可重建权重；
不能将其标记为五类真实机制采集和充分训练均已完成。
