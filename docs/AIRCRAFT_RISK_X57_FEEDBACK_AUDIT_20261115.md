# X-57/RCAIDE 历史评价的反馈可用性审计

PR105 与逐约束符号 GP 匹配的两个任务级基线是分阶段 GP 和直接可用标签 GP。符号相对分阶段的受限首解调用差为 −0.091（逆风）和 −0.083（增载），留一范围跨零。两种方法相对直接 GP 的平均首解调用都有稳定改善。三个臂均有首解后切换，因此这一比较涉及冷启动的风险统计分解。两个正式账本的提前终止都是 SOC 储备触发。结果提交 e082f52e276f13d27206b017032f06513df3e59a。

下一步先检查一个不同评价器能否支持同样的观测模型。使用真实执行过 RCAIDE 的历史 Compact MDA 资格恢复档案。它与 PR45 名为 true_aircraft 的降阶实验属于不同来源。按 55、65 nmi 分开检查，保留 37 次已启动费用、36 条结算观测和 1 条未结算记录。档案小且历史上中断，分析只用于确定下一轮可用哪些训练标签和对照。

## 审计内容

- 核对 2026-10-26 中断审计记录中的计划、提交、观测和 65 nmi 账本字节身份。重放两个账本的哈希链，核对逐条候选、任务、结算和契约；同时记录 55 nmi 账本的 SHA-256。
- 分开统计可信任务完成、有可用设计、已知隐藏失败、未知结果、可观测约束和明确区间。报告已知隐藏失败中有多少条仍提供至少一项非解析工程约束的可判定符号，并按约束统计。解析预检反馈单独标注。
- 求解器放电诊断及其来源单独记录。来自未通过原放电模型验证的试探根的数值缺少有效工程裕量标签。观察不到约束时保留缺失值。第 37 次的历史费用保留，完成与可行性为空。
- 该审计只读取已归档、经过当时适配器规范化的反馈。原始工件可能还有待校核的信息，需要先核实其物理含义和可观测时点，再进入模型。该工具不估计样本外性能、风险概率或优化收益。
- 若失败记录保留了足够且不同的非解析反馈，后续可在 X-57 合同中比较逐约束与分阶段模型。若记录主要只有任务级状态，下一轮优先验证分阶段模型，逐约束试验需另有经过验证的反馈定义。

## 工作机

使用本 PR 固定 SHA，在现有 Rcaide_vsp Python 3.9.25 运行 `python -m unittest discover -s tests -p "test_x57_feedback_audit.py"`。将 `--source` 指向历史 `qualification_recovered_20261025` 目录，即包含 `plan.json`、`submissions.jsonl`、`observations.jsonl`、`task_55/budget.jsonl` 与 `task_65/budget.jsonl` 的原始快照。历史位置是 `D:/LSBO/RA-LSBO/runs/compact_mda_20261021T081006Z_20eb608d/qualification_recovered_20261025`。用 `run_x57_feedback_audit.py --source <目录> --output <新报告.json>` 执行。输出位于历史目录和代码 worktree 外。用第二个新文件重复运行并校验两个报告字节相同。结果分支只归档报告、运行日志、代码 SHA 和校验和。历史目录缺失或哈希不合时保留日志和已找到的源路径，费用为 0。无需运行 RCAIDE 或加载原求解器。
