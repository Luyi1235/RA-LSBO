## 3. 原始轨迹定位到的失效机制

11个未发现可行解的RA运行共330个在线提案：

| 诊断 | 数量 | 解释边界 |
|---|---:|---|
| region GP选择网格最大连续长度1.0 | 330/330 | 模型选择记录，不是独立证明长度必然错误 |
| 选中局部增广候选 | 328/330 | 增广既含局部随机点，也含优化得到的点 |
| 选中候选与保存的SLSQP端点相同 | 283/330 | 不能把全部328点都归为SLSQP端点 |
| x和y都在设计盒角点附近 | 304/330 | 每个坐标距0或1不超过1e-6；不是可行域边界 |
| 与既往同构型候选数值近重复 | 108/330 | 活跃归一化维度L∞距离≤1e-8；用1e-6得到相同计数 |
| 最小乐观违反量回退 | 252/330 | 根据记录的fallback字段统计 |
| 门控后仅剩1个eligible候选 | 229/330 | 包含局部增广后的最终池 |
| 计划边界探索槽中的单候选退化 | 50/66 | 有边界探索标签不意味着真的有可选择的探索方向 |
| SLSQP裁剪告警 | 0 | 不能将这些失败归因于该警告 |
| 非有限/实质越界local_error | 0 | 不代表物理可行 |

330次选中region后验的EP都报告收敛；这些失败运行中未出现网格模型候选拟合错误。数值收敛与在未观测内部岛域上判断正确，是两件事。整个RA实验共有72条被计数的SLSQP裁剪告警，均发生在已找到可行点之后；所有RA提案中的local_error仍为0。部分暖启动前缀有未被选中的核候选拟合失败，应作为次级数值稳健性问题保留，而不是抹去。

最值得检验的解释链：只有违规符号且没有内部可行锚点时，基于当前证据选择的大相关长度可能把违规信息过度传播；局部求解持续追逐模型支持的边缘/角点；随着乐观支持减少，最小违反量回退将eligible集合压成单点；边界熵评分因没有选择空间而失效；严格哈希去重无法阻止浮点级近重复。这是与记录高度一致的机制假说，不是已完成的因果消融。

特别说明：没有对未送评候选作真值评价，故没有声称“池中某个真实可行候选确实被过滤掉”。不能把这里的设计域角点称为已知物理可行边界，也不能把这种轨迹称为VAE解码坍缩；当前局部搜索是固定离散分支后优化连续量。

## 4. 对照方法问题与解释范围

### 4.1 SEGO/UTB适配器的方向与原论文不同

运行快照使用g≤0约定，却在数值约束候选资格中使用mu+1.96*sigma≤0，这是保守收缩。原SEGO-UTB论文以g≥0约定表达mu+tau*sigma≥0；转换为本仓库g≤0后，应为mu-tau*sigma≤0，是乐观放宽。方向不同不是靠“适配版”标签就可以忽略的技术差异。

下一版应将历史算法明确标为保守UCB可行集适配器，或者另实现符号一致的UTB适配版本（仍须声明其他改编）。历史结果不得改名后冒充新方法结果。增加符号翻转等价性、sigma增大时探索域不应收缩、tau=0回到均值约束等测试。修正这一点也不能自动解释或修复它的所有停滞。

来源：Priem等，Upper Trust Bound Feasibility Criterion for Mixed Constrained Bayesian Optimization with Application to Aircraft Design，式(3)。
https://arxiv.org/html/2005.05067

### 4.2 LogCEI不是已发现max/min翻转，而是信息和拟合政策需要检查

记录中所有有log-EI的候选均为有限值；按保存的log-EI+log联合概率重新排序，与选中索引一致，未发现该评分的取最大方向错误。这只是记录内算术核对，不是完整后验重放。

Branin有394个log-EI模式步骤，其中252个由于历史精确目标少于2个，使用后备预测，整个池的log-EI恒定；Rosenbrock相应为469步中的135步。因此“log-EI模式”并不保证目标GP已经产生有效的空间区分。固定核超参数、不同代理训练政策和无局部优化，都可能影响强弱，需匹配检查，不能把全部差异解释为潜空间更好。

### 4.3 本轮覆盖的是精确值+符号删失，不是全部RA主张

全部7,716条结算记录状态为completed；6,518次目标missing，且同次region为严格正区间(0,+∞)，另外1,198次目标为exact。此处completed表示本次评价返回了合法记录，不等于设计可行或目标已得到。没有一般有限区间、多阶段物理异常或基础设施unknown的经验检验。数据模式并无造假，但论文应明确当前数学层实际检验的能力边界。

CBOB直接研究部分观测下的混合似然GP与平衡探索，应成为机制比较的优先对象；仅战胜本仓库外部适配器不能代替与最近邻工作的比较。
https://ojs.aaai.org/index.php/AAAI/article/view/29488

## 5. 分阶段推进，不先扩大昂贵评估

### P0：先形成独立修复候选与回归测试（不新增研究模型调用）

(1) 设计同离散构型、仅比较活跃归一化连续维度的近重复防护。保留原精确design_id作为证据身份，另加决策层距离检查和被拒绝原因。阈值必须按设计分辨率或数值理由预先定义，不能从结果中选最有利值；不可把近邻自动当作物理等价，也不应对有噪声且主动重复设计的任务盲目去重。候选耗尽必须可追踪回退而不是免费重复评价。

(2) 将可行发现和已有incumbent后的开发明确拆开。测试一种“首次可行前关闭连续局部求解，之后恢复原局部开发”的候选，保留现有模型/数据；另测试与模型门控独立的空间覆盖保底，不能让同一个过度自信模型把保底候选再次全部筛掉。只应用所有方法共享的合法解析预检查，不使用隐藏真值。

(3) 候选集退化时记录eligible数量、重复拒绝率、当前是否单类标签、region长度选择、无可行连续轮数；防止边界探索在单点集合中名义执行。不要只把boundary_fraction从0.2改成另一个数并宣称问题已解决。

(4) 修正/重命名SEGO适配器；检验LogCEI无/少目标数据时明确标记后备模型，核训练政策与RA的公平比较单列。不要同时无记录地大改全部基线与RA。

测试应覆盖严格区间端点、活跃维度掩码、近重复但不同类别不误杀、候选耗尽、回退仍消费预算、没有可行点时禁止虚构incumbent、符号翻转等价性、门控与覆盖策略冲突。原始算法及记录保持不动，新版本独立提交与新登记。

### P1：先做小而可归因的发现机制实验

推荐第一轮5个组：Random；原RA-v2；仅关闭首次可行前局部搜索；仅加入预先固定的覆盖保底（含近重复保护）；两者合并。除所研究的开关外保持模型、反馈、采集和初始化一致。覆盖保底中两个保护的独立贡献可在后续拆分，当前不声称每个子部件的因果效果。

使用当前20种子作开发性复验是可以的，但因为已查看全部结果，不能称为独立确认。保留全部种子和原任务，不只重跑失败种子，不通过改可行域来消除问题，不复用历史结果拼接新算法轨迹。5组各2题×20种子×30在线=6,000次在线；480共享初值+32面板+4锚点，完整上限6,516次数学模型调用，0次MDA。该数是建议规模，尚未登记、未授权执行、未运行；新smoke及测试内部廉价求值另计。若新增方法或面板必须重算预算。冻结后才能prepare/run，不能边跑边改。

有限预算判据：首可行发现率及首次可行成本优先；暖启动目标改进不能大幅退化；数值近重复浪费和单候选边界槽应显著减少；预算完整、失败均保留。判据阈值需运行前写入新协议；小样本不能据此宣称物理安全或普遍优势。

注意：纯覆盖保底是可靠性改进，不是充分的新算法创新。以当前均匀抽样可行质量p≈0.0862为例，6次独立随机抽样至少命中一次的概率只有1-(1-p)^6≈41.8%，30次约93.3%。即使真正分配20%预算给随机覆盖，也不能保证30步冷启动成功。这个计算只对当前分布与确定性可行集合成立，不是安全保证。

### P2：再检验论文真正的贡献

在可靠发现策略固定后，至少补入：层级one-hot+相同局部搜索+相同部分观测GP；原冻结LSBO；“随机发现+同等局部开发”的简单混合对照；CBOB或忠实的透明适配。将表示{潜空间、层级one-hot}与反馈{精确数值、精确+符号、精确+一般合法区间}交叉比较，防止把强局部搜索的贡献误记到表示或区间模型上。当前数学任务的区间大多等同符号，无法单独证明一般区间信息的增量。

重点研究假说是：在单类/部分观测阶段，如何避免表示和约束后验过早排除尚未发现的层级分支，并在信息充分后恢复高效开发。可考察约束核尺度先验或模型平均，但不能把强制短长度、打开kernel averaging当作已证明有效的补丁；每项要有匹配消融。

下一版算例要有非平凡构型权衡、内部分离可行岛与多阶段区间反馈，任务规则先冻结再比较。不能仅把现有椭圆位置移动到算法喜欢的地方，或设计让RA预期获胜的函数。原两题保留作为失败案例和发展记录。

### P3：冻结后独立确认，再升级飞机保真度

新种子与新任务实例应在算法冻结后生成；登记主要终点、多重比较范围、未知结果处理和所需样本精度。每次把完整种子配对作为统计单位，不能把多轮或多候选当独立重复。报告发现率/删失成本、全种子达标概率、配对终点以及带分母的条件目标指标，并保留运行时间开销。当前数学单trial中RA约一分钟，而Random约0.3秒，是真实计算代价，不应在昂贵评价次数之外隐去。

只有在数学发现机制和简化飞机部分反馈验证达到预设判据后，才制定新的RCAIDE MDA预算与风险检查。飞机扰动场景依然属于优化后验证，不能变成机会约束/CVaR优化或安全认证的证据。
